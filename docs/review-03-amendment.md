## 确认的产品与技术规则

1. 每天 Asia/Shanghai 00:00 开始新的统计、榜单及圈子。服务器每次请求按权威日期查询当天记录，无记录为0；不依赖定时任务或客户端打开才重置，不删除/覆盖昨日历史，不操作 Apple Health 原始数据。继续拒绝旧日快照，保留等待写锁跨午夜的验证。
2. 集中定义 `CIRCLE_STEP_WIDTH=1000`。步数区间编号为 `steps // 1000`，区间下限 `编号*1000`、上限 `下限+999`；每100步1虚拟楼层和最大合法步数1000000规则不变。最高合法步数仍属于按公式计算的区间，不能以分组扩大合法上传范围。999与1000必须分圈，精确相同步数必同圈。
3. 圈子/组/频道为同一空间，以「上海日期+区间编号」形成稳定服务端标识。注册后明确同意公开及参与的用户自动归入当天区间，未同步为0；跨区同步立即迁圈，新日按新日期重配。建议基于当日快照动态派生成员，不保存独立人数计数，避免多圈重复、定时任务失效及并发漂移。
4. 采用独立主动参与选择：新增持久圈子参与记录，旧账号和新注册默认未参加；不能把过去的排行榜共享同意当作已看过圈子提示。允许先本地运动或只共享排行榜，不强制参加。首次参加明确告知每日1000步分组及昵称、当日汇总步数/楼层公开。只有 `sharing_enabled && participating` 才公开入圈。
5. 参与接口与现有共享操作使用同一 `consent_revision` 串行化。参与变化及每次成功退出均推进持久版本；撤回共享同时关闭参与；删除全部共享步数关闭共享和参与、推进版本；账号删除级联移除。旧开启/上传/参加请求在重启后也不能恢复资格。只重新开启排行榜共享不能恢复圈子参加；须再次主动参加。
6. 使用真实HTTP返回当前频道、日期、规则、区间、总人数、可遍历分页成员及本人标记/位置。成员昵称、当日步数、楼层只来自服务器真实记录，认证要求与排行榜一致。明确当前频道页面仅向参与者返回本人区间，非参与者返回当前圈子为空、成员空列表；不能据客户端 user_id 或任意日期授权。圈子分页游标须绑定频道/区间、日期、数据版本和页容量；迁圈、跨日、成员/昵称/隐私变化后要求刷新，不能把旧频道当今日。
7. 小圈展示真实人数，允许只有本人，不混区或虚构用户。频道首先是成员共享空间，完整即时聊天不属于本增量验收。
