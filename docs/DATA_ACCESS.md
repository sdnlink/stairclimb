# PostgreSQL 访问边界与复现实验

本模块承接需求版本7的优化授权，保留 Rust＋PostgreSQL、邮箱认证、全程HTTPS、健康共享及圈子独立同意。没有改动已接受的 Swift 界面，也不表示最终集成交付完成。

## 连接与事务

`STAIRCLIMB_DB_POOL_MAX` 默认8，允许1～64；`STAIRCLIMB_DB_POOL_TIMEOUT_MS` 默认1500，允许10～30000。配置通过环境传入，示例均显式export；非法值启动失败。每个进程共用一个池，克隆Application不会增加池。上限包括正在创建、空闲和已借出的连接。等待超过获取期限返回 `503 database_busy`，创建失败返回脱敏 `503 storage_unavailable`。

连接创建在已计入上限的后台工作中进行，获取期限也覆盖数据库握手不响应；超时不会释放仍在创建的配额或无限建立新连接。迟到的连接进入空闲池，创建失败释放配额。底层socket连接有超时，但DNS/认证阶段可能保持工作线程和配额，直至底层调用结束；此时调用者仍按获取期限返回，池最多占用配置数量的连接创建线程。应修复数据库网络/认证，必要时重启本任务服务。此MVP没有后台连接保活、自动请求重放或连接公平排队保证。

每个租约独占同步Client；正常返回、API错误及事务回滚后通过Drop归还。已观察到关闭的Client被丢弃，之后按需补建。静默断开的空闲连接可能使下一次查询返回503，观察到关闭后丢弃，后续请求重新建立连接；客户端仍应重新获取当前状态，不自动重放健康数据或删除操作。事务保持5秒语句超时、4秒锁等待超时。获取超时不等于整个业务请求超时。

## 锁与隐私

写事务不再在开始时锁住全局榜单版本。账号相关操作的共同顺序是：必要时锁邮箱摘要的事务级advisory key → 按ID排序锁用户行 → 认证/同意/会话/凭据/步数子记录 → 若公开内容改变，最后更新榜单版本行 → 提交。没有持有全局版本锁后再锁用户的路径。注册邮箱唯一约束继续兜底；邮箱锁也协调未验证旧身份的独立注册，保持不接管旧数据。

写入先找凭证对应的用户，再锁用户行，**取得锁后重新认证并取当前时钟和同意版本**。刷新、退出、密码重置、一次性凭据消费和账号删除同样锁定相关用户并重查条件。登录清理只涉及本人过期会话，避免跨账号子行锁顺序反转。撤回/删除的持久版本屏障没有移除。全局版本行仍短暂串行化公开变化，确保任何已提交变更都令旧分页失效；它不是被取消或换成不可靠的非事务计数。

步数写入取得用户锁后校验日期，并在可能等待全局版本锁后、提交之前再次校验日期。后一次校验失败会回滚步数、圈子派生影响及版本修改，不把旧日请求写入新日，也不修改旧日历史。

实现依据[PostgreSQL行锁及一致锁顺序](https://www.postgresql.org/docs/current/explicit-locking.html)。具体正确性以本项目真实数据库并发测试为证据。

## 数据库分页

保持原有日期＋版本快照、limit绑定游标、稳定ID次序、并列RANK、本人位置及圈子契约。一次repeatable-read事务内分别查询COUNT和当前页；PostgreSQL执行窗口排名与 `ORDER BY position LIMIT/OFFSET`，只把至多limit个成员返回Rust。本人定位查询只返回匹配用户的一行，不再在Rust里查找完整榜单。未同步用户由LEFT JOIN派生0步。

迁移003增加日期/步数/用户索引、公开用户和圈子参与的部分索引，以及认证计数过期清理索引。旧库和SQLite导入工具均顺序应用迁移，保留数据。排行榜含零值派生和精确排名，数据库仍可能扫描并排序整个候选集合；COUNT也需处理全部候选。深OFFSET仍有额外成本，索引不能保证每种规模/分布都被优化器选择。该改动约束的是数据库连接数及应用每页接收的成员数量，不承诺数据库查询为常数时间。参考[PostgreSQL LIMIT/OFFSET及稳定排序说明](https://www.postgresql.org/docs/current/queries-limit.html)。

## 实验

```sh
python3 scripts/benchmark_data_access.py --users 10000
# 对照改动前二进制（保留在本机忽略目录，有SHA-256记录）
python3 scripts/benchmark_data_access.py --binary .runtime/data-access/before-server --users 10000
```

工具只使用随机临时schema、临时端口和虚构昵称；不创建外部邮箱或发送邮件。单独的真实邮箱/HTTPS/隐私回归由原固定测试继续执行。每次实验清理schema和Rust进程，不影响开发实例。基线来自本轮编辑前保存的测试二进制，对应已接受检查点 `d01f49dbadd87e0b9b1ceb185a2fce7b872cd28b`；如需重新编译，可将该版本以 `git archive` 导出到临时目录，执行 `cargo build --locked --manifest-path <导出目录>/backend/Cargo.toml --features test-support --bins` 后将其测试二进制传给 `--binary`，无需切换工作区或Git引用。

实际结果见 `docs/validation/data-access-before.txt` 与 `data-access-after-final.txt`，两者退出0，规模均为1万用户、同日同圈500步、每页20人；分别顺序读取12次榜单及12次圈友，随后8个worker完成32次榜单请求。均为本机debug构建，缓存、调度及后台检查影响测量，不可当作吞吐承诺。

| 榜单中位延时(ms) | 231.559 | 184.205 |

圈友延时在这次实验中增加；COUNT和窗口查询仍有成本，不能声称所有接口提速。RSS包含分配器保留内存，仅为一次观测。确定的结构变化是每页不再把1万人读入Rust，连接可复用且受限，无变化/私人账号写入不再占用榜单版本锁。公开数据变化仍会使全部旧页失效。
